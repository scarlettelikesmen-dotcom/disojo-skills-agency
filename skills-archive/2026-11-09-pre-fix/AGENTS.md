## 7. Senior Engineering Standards (The "Anti-Vibe Coding" Laws)

Disojo software must never look or perform like amateur AI "vibe code". Every system must meet institutional-grade standards across Database, Web, and Mobile:

### 7.1 Database & Backend Engineering
* **Database Indexing:** All foreign keys and high-frequency filter columns (`student_id`, `batch_id`, `created_at`) must have explicit B-Tree indexes.
* **Zero N+1 Queries:** Never run queries inside loops. Always use joined relations or consolidated batch lookups.
* **Connection Pooling:** All database traffic must route through Supabase connection poolers (PgBouncer/Supavisor) to prevent exhaustion under spike traffic.
* **Query Caching:** Heavy analytical and dashboard aggregations must be cached with defined invalidation windows.
* **Row-Level Security (RLS):** Every Supabase table must have strict RLS policies enabled. Zero unrestricted public access.

### 7.2 Web Performance (Lighthouse 90+ Standard)
* **Lighthouse Performance Gate:** All public and portal web routes must score 90+ across Performance, Accessibility, Best Practices, and SEO.
* **Loading Skeletons 💀:** Never display raw blank screens or isolated center spinners. Implement shimmering skeleton wireframes.
* **Input Debouncing:** Search inputs and auto-saving forms must be debounced by 300ms minimum.
* **Payload Compression:** API payloads compressed via Brotli/Gzip; all static imagery served as `.webp` via global CDN.
* **Pagination:** Large datasets must use cursor-based pagination or infinite scroll (limit: 20–50 items/page).
* **Zero Unused Dependencies:** Audit `package.json` regularly. Never install a multi-megabyte dependency for trivial functions.

### 7.3 Mobile App Performance (React Native / Expo)
* **Shopify `FlashList`:** Standard `FlatList` is prohibited for lists over 15 items. Always use `FlashList` with cell recycling for 60–120 FPS performance.
* **Native Thread Animations:** All gestures and animations must execute on the native C++ UI thread via `react-native-reanimated`.
* **Hardware-Encrypted Auth:** Tokens stored strictly in `Expo SecureStore` (iOS Keychain / Android Keystore). Silent background JWT refresh prevents unexpected session logouts.
* **Hermes Bytecode Pre-compilation:** Hermes engine enabled on all production builds for sub-second cold starts and reduced RAM footprint.
* **Optimistic UI Updates:** Action buttons (e.g. attendance, booking) must update the UI immediately (0ms latency) while network syncs resolve in background.
* **Image Caching & Blurhash:** All remote imagery served via cached fast-image components with pre-warmed Blurhash placeholders to prevent layout shifts.
